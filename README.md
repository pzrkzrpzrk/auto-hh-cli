# auto-hh-cli

Автоматизация поиска, отбора и отклика на вакансии **hh.ru**: поиск через публичный API, отсев «мусора» локальным фильтром, оценка пригодности ИИ-судьёй, генерация персональных сопроводительных и автоотклик через браузер (Playwright).

> ⚠️ **Важно.** Соискательский API hh.ru закрыт (15.12.2025), поэтому отклики выполняются через **Playwright** (браузерную автоматизацию). Это нарушает пользовательское соглашение hh.ru и может привести к блокировке аккаунта. Используйте на свой страх и риск — лучше с тестового аккаунта и без агрессивных интервалов.

---

## Как это работает

Полный цикл «поиск → отклик» разбит на независимые шаги — все они запускаются из **интерактивного меню** (`npm start`):

1. **`search`** — собрать вакансии с hh.ru в кэш: страницы выдачи и описания (полные карточки). Ни фильтра, ни ИИ, ни писем.
2. **`digest`** — по кэшу поиска: локальный фильтр → ИИ-судья → **дайджест** (файл + MongoDB).
3. **`cover`** — сопроводительные письма для вакансий дайджеста (батчами, с кэшем).
4. **`apply`** — открыть сохранённую сессию браузера и откликнуться, подставляя готовые письма.

```
hh.ru ──Playwright──▶ search: страницы выдачи (cachePages) + описания (cacheFull)
                                        │
                                        ▼
             digest: локальный фильтр (навыки, исключения, ЗП) ── пропуск
                        └─▶ ИИ-судья: score 1–10, вердикт fit/no-fit
                                └─▶ дайджест (digest-ГГГГ-ММ-ДД.md + MongoDB)
                                        │
                                        ▼
             cover: генерация сопроводительных под каждую вакансию
                                        │
                                        ▼
       apply ──Playwright──▶ браузер (сохранённая сессия) → отклики на hh.ru
```

Порядок важен: `digest` читает кэш последнего `search`, `cover` — последний дайджест, `apply` — письма, сохранённые шагом `cover`.

> ℹ️ `search` тянет не только страницы выдачи, но и **описания вакансий** (`cacheFull`) — по одной карточке на вакансию, поэтому шаг занимает минуты, а не секунды (≈3 с на карточку при `REQUEST_DELAY_MS=1500`). Уже скачанное и вакансии из истории пропускаются: повторный запуск быстрый, а Ctrl+C ничего не теряет — прогресс лежит в MongoDB. Если описаний всё же не хватит, `digest` и `cover` догрузят их сами.

## Установка

Требования: **Node.js 18+**, запущенный **MongoDB** (проще всего через `docker-compose`).

```bash
# 1. Зависимости и браузер Playwright
npm install
npx playwright install chromium

# 2. Конфигурация
cp .env.example .env          # затем заполните .env (см. ниже)
# config.json уже есть в репозитории — отредактируйте его под себя

# 3. MongoDB (опционально, если нет своего инстанса)
docker compose up -d          # поднимет mongo + mongo-express (localhost:8081, admin/admin)

# 4. Применить миграции MongoDB (индексы, коллекции)
npm run migrate:up

# 5. Резюме
#    Один файл:  задайте RESUME_PATH=./resume.md в .env
#    Несколько:  RESUMES_DIR=./resumes (каждый файл .md/.txt/.pdf = отдельное резюме)
```

Запуск не требует компиляции — CLI исполняет TypeScript напрямую через `tsx`. Скрипт `npm run build` (`tsc`) нужен только если вы собираете чистый JS.

## Резюме

Инструменту нужно ваше резюме — ИИ читает его и сравнивает с каждой вакансией (оценка пригодности и сопроводительные). Поддерживаются форматы `.md`, `.txt`, `.pdf`.

### Шаг 1 — положите файл резюме

Создайте директорию `resumes/` в корне проекта и положите туда резюме:

```
resumes/ivan.md
```

### Шаг 2 — укажите резюме в `.env`

Два режима:

| Режим | Переменная | Описание |
| --- | --- | --- |
| Одно резюме | `RESUME_PATH=./resume.md` | Путь к одному файлу |
| Несколько | `RESUMES_DIR=./resumes` | Директория; имя файла без расширения = имя для пункта меню «🧾 Резюме» |

> ℹ️ Переменная называется **`RESUMES_DIR`** (с «S») — в `.env.example` она задана правильно. Старое имя `RESUME_DIR` не читается.

> ℹ️ Если `RESUME_PATH` указывает на несуществующий файл, инструмент пишет предупреждение в лог и берёт первое резюме из `RESUMES_DIR` (раньше в этом случае резюме молча считалось отсутствующим).

### Шаг 3 — поднимите MongoDB и примените миграции

```bash
docker compose up -d
npm run migrate:up
```

> ℹ️ Настройки migrate-mongo лежат в `migrate-mongo-config.js` в корне проекта — указывать `-f` не нужно. Файл берёт `MONGODB_URI` и `MONGODB_TIMEOUT_MS` из `.env`, поэтому миграции применяются к той же базе, что и остальные команды. Статус миграций: `npx migrate-mongo status`.

### Шаг 4 — зарегистрируйте резюме в базе

Регистрация добавляет резюме в коллекцию `resumes` MongoDB — это привязка вердиктов ИИ, сопроводительных и кэша к конкретному резюме через `resumeId`.

Регистрация происходит **автоматически** при сборке дайджеста (пункт меню **🧠 Собрать дайджест**), если резюме загружено.

Либо **вручную** — пункт меню **🧾 Резюме**:

| Подпункт | Что делает |
| --- | --- |
| 🎯 выбрать активное | Выбрать резюме из `RESUMES_DIR` — подставится в `digest` / `cover` / `grade` / `schedule` в текущей сессии меню |
| `list` | Показать доступные резюме |
| `show` | Показать содержимое резюме (например `resumes/ivan.md`) |
| `register` | Зарегистрировать резюме в MongoDB |

Имя `<name>` — имя файла без расширения; файл должен лежать в `RESUMES_DIR`.

> В базу сохраняются только метаданные — `resumeId`, `name`, `filename`, `createdAt`. **Сам текст резюме в MongoDB не загружается**: он всегда читается из файла на диске при каждом запуске.

## Быстрый старт

```bash
npm start
```

Дальше — пункты меню по порядку:

1. **🔑 Войти на hh.ru** — откроется браузер, залогиньтесь вручную и закройте его. Сессия сохранится в `./data/browser-profile`.
2. **🔍 Поиск вакансий** — вакансии уедут в кэш (страниц берётся столько, сколько задано в `config.search`).
3. **🧠 Собрать дайджест** — локальный фильтр → ИИ-судья → дайджест.
4. **📄 Последний дайджест** — посмотреть, что отобралось.
5. **✉️ Письма для дайджеста** — сопроводительные для вакансий дайджеста.
6. **🚀 Отклики из дайджеста** — автоотклик через Playwright.

> ℹ️ Меню — **единственная** точка входа CLI: подкоманд у `auto-hh` больше нет, все шаги запускаются только из него.

**Во время `apply`** скрипт для каждой вакансии сам заполняет сопроводительное, но **финальную кнопку «Откликнуться» вы нажимаете вручную** в браузере — это защита от случайных откликов. Вакансии, для которых письмо ещё не сгенерировано (шаг `cover` пропущен), **пропускаются**. Если на вакансии есть тестовое задание, по умолчанию (`PW_TEST_MODE=manual`) скрипт приостановится, а вы пройдёте тест и нажмёте ENTER в консоли.

## Интерактивное меню

Запуск:

```bash
npm start           # или: npm run ui, npx auto-hh, npx auto-hh ui (алиасы: menu, interactive)
```

Меню — тонкая обёртка над шагами пайплайна: своих правил, настроек и кэша у него нет, ответы на промпты превращаются в те же аргументы, которые раньше принимали команды.

| Пункт меню | Что делает |
| --- | --- |
| 🔍 Поиск вакансий | Собрать вакансии с hh.ru в кэш; спрашивает, сбрасывать ли историю и кэш перед поиском |
| 🧠 Собрать дайджест | Локальный фильтр → ИИ-судья → дайджест; спрашивает резюме, ИИ-судью, лимит и dry-run |
| ✉️ Письма для дайджеста | Сопроводительные для вакансий дайджеста: резюме, лимит, перегенерация готовых писем |
| 🚀 Отклики из дайджеста | Отклики через Playwright: тип (`latest`/`all`) и лимит |
| 🔑 Войти на hh.ru | Открыть браузер и войти вручную — сессия сохранится в профиль |
| 📄 Последний дайджест | Показать последний дайджест (можно в JSON) |
| 🕓 История откликов | Показать историю просмотров и откликов (можно в JSON) |
| 🧾 Резюме | Выбрать активное резюме списком из `RESUMES_DIR` + `list` / `show` / `register` |
| 🎯 Оценить резюме ИИ | Оценка резюме «глазами рекрутера» → `resume-grade.md` |
| ✉️ Письмо по id | Одно сопроводительное для вакансии по id (ввод id и выбор резюме) |
| ⏰ Планировщик | Шаги из `config.schedule.steps` по cron; блокирующий, выход по Ctrl+C |
| ⚙️ Конфигурация | Показать текущий `config.json` (только просмотр) |
| 🧹 Сброс данных | Сбросить историю, кэш и дайджесты (файлы + MongoDB) — с подтверждением |

- **Активное резюме** показывается в шапке меню (`Резюме: pavel (pavel.txt)`) и подставляется по умолчанию в шаги `digest`, `cover`, `grade` и `schedule`. Выбор живёт только в текущей сессии меню — на диск ничего не пишется; пункт «Резюме → 🎯 выбрать активное» умеет вернуть «как в .env». Вне меню «активного» резюме нет: шаги берут `RESUME_PATH` / первый файл из `RESUMES_DIR`, а планировщик — резюме, выбранное в меню при его запуске.

- **Ctrl+C** внутри промпта (и `Esc`) — выход из меню; Ctrl+C во время самого шага (`search`, `digest`, `cover`, `apply`, `schedule`) прерывает его как обычно.
- Меню требует **TTY**: при запуске из пайпа или в CI (`process.stdout.isTTY === false`) оно печатает подсказку и завершается с кодом 0. Отсюда же следствие: **планировщик запускается только в обычном терминале** — в cron или планировщике задач Windows без TTY его не поднять.
- Ручной ENTER в браузерных флоу (`PW_TEST_MODE=manual`, капча) работает так же, как раньше: меню закрывает свои промпты до старта шага и не держит stdin.
- Промпты — на [`@inquirer/prompts`](https://www.npmjs.com/package/@inquirer/prompts) версии 7 (есть CJS-сборка, Node 18+).

## Команды

Подкоманд у CLI больше нет: `auto-hh` открывает интерактивное меню, а все шаги пайплайна собраны в его пунктах (таблица выше).

### npm-скрипты

| Скрипт | Что делает |
| --- | --- |
| `npm start` | Открыть интерактивное меню (то же, что `npx auto-hh`) |
| `npm run ui` | То же меню явной командой: `npx auto-hh ui` (алиасы: `menu`, `interactive`) |
| `npm run build` | Компиляция TS в JS (не обязательна) |
| `npm run migrate:up` | Применить миграции MongoDB |
| `npm run migrate:down` | Откатить последнюю миграцию |
| `npm run migrate:create` | Создать новую миграцию |

Любой другой аргумент (`npx auto-hh search`, `npx auto-hh digest`) отвечает подсказкой: «Команд больше нет — все шаги делаются в интерактивном меню».

## config.json

```text
{
  "search": { ... },     // запрос к API hh.ru
  "filter": { ... },     // локальный пре-фильтр
  "apply":  { ... },     // пороги и шаблоны
  "api":    { ... },     // ИИ-провайдер (OpenAI-совместимый)
  "schedule": { ... },   // cron для пункта меню «⏰ Планировщик»
  "adaptResume": true    // адаптировать резюме под вакансию перед письмом
}
```

### `search` — запрос к hh.ru

| Поле | Что задаёт |
| --- | --- |
| `text` | Поисковая строка (поддерживает `OR`, `AND`, скобки) |
| `area` | ID региона hh — `null` = вся Россия, `[1, 2]` = список регионов |
| `remote_area` | Регионы, где берём **только удалённые** вакансии: поиск идёт отдельным проходом с принудительным `schedule=remote`. `[113]` — все регионы России, `[]` — выключено. |
| `experience` | Опыт: `between1And3`, `between3And6`, … |
| `salary` | Минимальная ЗП |
| `currency` | `RUR`, `USD`, … |
| `only_with_salary` | Только вакансии с указанной ЗП |
| `schedule` | График: `remote`, `flexible`, … |
| `employment` | Занятость: `full`, `part`, `project`, … |
| `per_page` | Вакансий на странице (≤ 100) |
| `start_page` | С какой страницы начинать (0 = первая) |
| `max_pages` | Сколько страниц обойти, считая от `start_page` |
| `search_period` | Только вакансии, опубликованные за последние N дней (`null` — без ограничения) |
| `order_by` | Порядок выдачи: `relevance` (по соответствию), `publication_time` (по дате), `salary_desc`, `salary_asc` |

> ⚠️ При смене `order_by` или `search_period` запускайте пункт меню «🔍 Поиск вакансий» со включённым сбросом: кэш страниц ключуется только по номеру страницы, поэтому страницы 1..N иначе подтянутся из прошлого прогона со старой сортировкой (страница 0 перезапрашивается всегда).

> ℹ️ `remote_area` — регионы «только удалёнка»: страницы такого прохода кэшируются под ключами `remote:N`. Меняя список регионов (или включая/выключая `remote_area`), запускайте «🔍 Поиск вакансий» со сбросом, иначе страницы 1..N подтянутся из прошлого прогона.

### `filter` — локальный пре-фильтр

| Поле | Что задаёт |
| --- | --- |
| `requiredSkills` | Список — хотя бы один навык должен встретиться в описании |
| `excludedKeywords` | Слова, при наличии которых вакансия отбрасывается |
| `excludedCompanies` | Компании, которые игнорируем (подстрочное совпадение по названию работодателя, регистр не важен). Личный список удобнее держать в `.env` → `EXCLUDED_COMPANIES` — он **перебивает** это поле |
| `excludeArchived` | Пропускать архивные вакансии |
| `locationRule` | Правило локации: в регионах из `search.area` (по умолчанию Москва/СПб) — любые вакансии, в остальных — только удалёнка. `false` отключает правило. |

> ℹ️ Личный блэклист компаний держите в `.env` → `EXCLUDED_COMPANIES` (через запятую): `.env` не попадает в git, а `config.json` — отслеживается. Если переменная не задана или пуста, работает список из `config.json`. Разделитель — запятая, поэтому внутри названия её быть не может: указывайте фрагмент имени (совпадение подстрочное).

### `apply` — пороги и шаблоны

| Поле | Что задаёт |
| --- | --- |
| `maxPerRun` | Максимум вакансий в один дайджест (перебивается лимитом в пункте меню «🧠 Собрать дайджест») |
| `dryRun` | Если `true` — пункт «🧠 Собрать дайджест» по умолчанию работает как dry-run |
| `minClaudeScore` | Нижний порог score ИИ-судьи, всё ниже отбрасывается |
| `coverLetterTemplate` | Фолбэк-шаблон письма (шаг `cover`), если ИИ недоступен. Плейсхолдеры: `{title}`, `{employer}`, `{area}`, `{signature}` (подпись из `COVER_SIGNATURE`) |

### `api` — ИИ-провайдер

| Поле | Что задаёт |
| --- | --- |
| `baseUrl` | Базовый URL OpenAI-совместимого API. В репозитории прописан Z.ai: `https://api.z.ai/api/paas/v4/` |
| `apiKey` | Ключ. Запасные источники: `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` в `.env` |
| `model` | Модель для судьи, писем и оценки резюме. По умолчанию `glm-4.7-flash`; перебивается переменной `CLAUDE_MODEL` |

Если ключ не задан — ИИ-судья и генерация писем выключаются, остаётся только локальный фильтр.

### `schedule`

| Поле | Что задаёт |
| --- | --- |
| `cron` | Cron-выражение (5 полей). Пример: `0 12 * * *` — каждый день в 12:00 |
| `steps` | Какие шаги выполнять по расписанию: `["search", "digest", "cover"]` по умолчанию. Можно оставить только `["search"]` и т.п. |

### `adaptResume`

Булевый флаг: адаптировать резюме под конкретную вакансию перед генерацией сопроводительного (`true` по умолчанию).

## Переменные окружения (`.env`)

### Базовые

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `CONFIG_PATH` | `./config.json` | Альтернативный путь к конфигу |
| `EXCLUDED_COMPANIES` | — | Личный список исключаемых компаний через запятую (например `Яндекс,Сбер,Т-банк`): пробелы вокруг значений обрезаются, дубликаты схлопываются. Перебивает `config.json` → `filter.excludedCompanies` |
| `HH_USER_AGENT` | `AutoHH/1.0` | User-Agent для API hh.ru — рекомендуется указать ваш email |
| `RESUME_PATH` | — | Путь к **одному** резюме (`.txt`, `.md`, `.pdf`) |
| `RESUMES_DIR` | — | Директория с **несколькими** резюме. Выбор: пункт меню «🧾 Резюме» → 🎯 выбрать активное |
| `APPLICANT_PROFILE` | `опытный разработчик` | Краткое описание соискателя — попадает в системный промпт ИИ |
| `REQUEST_DELAY_MS` | `1500` | Пауза между запросами к API hh.ru |
| `MONGODB_URI` | `mongodb://localhost:27017/autohh` | URI MongoDB для кэша, истории и дайджестов |
| `MONGODB_TIMEOUT_MS` | `10000` | Таймаут подключения к MongoDB: если база недоступна, команда сообщит об этом быстро, а не через 30 с |
| `DEBUG` | — | Любое непустое значение включает `log.debug` |

> ℹ️ Переменная называется **`RESUMES_DIR`** (с «S») — в `.env.example` она задана правильно; старое имя `RESUME_DIR` не читается. Если `RESUME_PATH` указывает на несуществующий файл, резюме не загрузится и ИИ-шаги будут отключены (в логе — `RESUME_PATH not set`).

### ИИ

| Переменная | По умолчанию | Что задаёт |

| `OPENAI_API_KEY` | — | Ключ провайдера (проверяется раньше `ANTHROPIC_API_KEY`), если не задан `api.apiKey` |

## Замечания и отладка

- **Селекторы hh.ru меняются** — если автоотклик перестал работать, смотрите `data/app.log` и обновите массивы `respondSelectors`, `submitSelectors` и т.п. в `src/cli/cmd-apply.ts`.
- **Тесты в вакансии.** По умолчанию (`PW_TEST_MODE=manual`) скрипт ставит окно браузера на передний план и ждёт ENTER в консоли — проходите тест вручную, отправляете отклик, затем ENTER → следующая вакансия. Режим `skip` пропускает такие вакансии. Ручной режим работает только при `PW_HEADLESS=false`.
- **Ручное подтверждение отклика.** `apply` заполняет письмо, но не жмёт кнопку сам — вы нажимаете «Откликнуться» в браузере (защита от случайного). Таймаут ожидания — `PW_MANUAL_TIMEOUT_MS`.
- **Лимит hh.ru** — ~200 откликов в день, не превышайте (задаётся `maxPerRun`).
- **Порядок шагов.** Пункт «🧠 Собрать дайджест» без предварительного поиска скажет «Кэш поиска пуст»; «✉️ Письма для дайджеста» без дайджеста — «Дайджест пуст»; «🚀 Отклики из дайджеста» пропускает вакансии, для которых нет письма (сгенерируйте: пункт меню «✉️ Письма для дайджеста»).
- **dry-run** в пункте «🧠 Собрать дайджест» ничего не записывает: ни дайджест, ни историю просмотров — удобно проверять фильтр и лимит.
- **Свой путь к конфигу.** Флага `-c, --config` больше нет: путь к `config.json` задаётся переменной `CONFIG_PATH` в `.env` (по умолчанию `./config.json`).
- **ИИ без ключа.** Без `api.apiKey` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` судья и письма отключаются — работает только локальный фильтр.
- **Модель и провайдер живут вместе**: `api.baseUrl` и `api.model` в `config.json` (перебить модель можно через `CLAUDE_MODEL`). Для Z.ai — `https://api.z.ai/api/paas/v4/` + `glm-4.7-flash`, для DeepSeek — `https://api.deepseek.com` + `deepseek-chat`.
- **GLM-4.7-Flash думает всегда.** У GLM-4.7 режим рассуждений принудительный: ответ приходит медленнее и часть лимита `AI_MAX_TOKENS` уходит на «размышления». Если нужен другой баланс — `glm-4.7-flashx` (платная, дешевле `glm-4.7`) или `glm-4.7`.
- **429 на бесплатном тарифе**: ставьте `AI_CONCURRENCY=1` — параллельные запросы на free-тарифе только бьют в общий лимит. Повторы делает `AI_RETRY_*`: паузы растут экспоненциально со случайным разбросом (jitter), чтобы параллельные запросы не повторяли синхронно одним залпом, а `Retry-After` от сервера учитывается как есть.
