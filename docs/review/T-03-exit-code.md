# T-03 — Единый выход из команд вместо `process.exit`

- **Приоритет:** **P0** — REVIEW.md § IV **F1**
- **Этап:** 0 (гигиена, но влияет на корректность)
- **Зависимости:** нет
- **Объём:** 2 файла, 6 вызовов

## Проблема

`src/cli/cmd-resume.ts:31,36,48,52` и `src/cli/cmd-schedule.ts:69,77` вызывают `process.exit(1)`
(все шесть — внутри функций: `cmdResumeRegister` :28-41, `cmdResumeShow` :42-69, `cmdSchedule` :62-115,
то есть замена на `exitCode` + `return` безопасна).

Единая точка входа — `bin/auto-hh:4` → `run()` (`src/cli/index.ts:101-110`). Через неё идут **и** 12
зарегистрированных подкоманд (`index.ts:23-97`), **и** меню `ui`/`menu`/`interactive` (`:93-97`);
`run()` закрывает MongoDB **в `finally`**:

```ts
} finally {
  await closeDb().catch(() => {});
}
```

`process.exit(1)` завершает процесс немедленно: `finally` не выполняется, соединение с Mongo не закрывается,
и пользователь вылетает из приложения после одной неудачной команды вместо возврата в меню (или вместо
штатного завершения CLI-вызова).

Правильный стиль уже используется в остальных местах: `process.exitCode = 1` — `cmd-ui.ts:400`,
`cmd-cover.ts:42,148`, `cmd-digest.ts:309`, `cmd-apply.ts:267`, `src/cli/index.ts:106`.
Отдельный случай — легаси-обёртка `src/apply-playwright.ts:15,18`: она не входит в CLI-контракт,
её судьба решается в T-02.

## Что сделать

- [x] `cmd-resume.ts`: заменить `process.exit(1)` (`:31,36,48,52`) на `process.exitCode = 1` + `return`.
- [x] `cmd-schedule.ts`: то же для `:69,77`.
- [x] Если внутри есть `process.exit(0)` или ранние выходы — привести к тому же виду
      (в `src/cli/` таких не было; `process.exit(0)` остался только в легаси-обёртках — см. T-02).
- [x] Договориться о контракте: команды **никогда** не вызывают `process.exit`; выход из процесса — только
      в `src/cli/index.ts` через `exitCode`. Добавить это одной строкой в комментарий-шапку `index.ts`
      (после T-02 там останется ровно один комментарий).

## Проверка

```powershell
Get-ChildItem src -Recurse -Include *.ts | Select-String -Pattern 'process\.exit\('
npx tsc --noEmit
npx tsx bin/auto-hh ui
```

## Риски

Низкий. Единственная тонкость: если `process.exit(1)` стоял в обработчике внутри `try/catch`, замена на
`exitCode` + `return` может «протащить» управление дальше по коду — проверить каждый из 6 вызовов вручную
и убедиться, что после него не остаётся логики, выполняющейся при ошибке.

## Реализовано

- Все 6 вызовов заменены на `process.exitCode = 1; return;` — **6 из 6**: `cmd-resume.ts:31,36,48,52`,
  `cmd-schedule.ts:69,77`. В `cmd-resume.ts` два случая были внутри `try/catch` (`cmdResumeShow`) — `return`
  из `catch` сохраняет анализ потока данных (`resume` остаётся определённо присвоенным), tsc это подтвердил.
- Контракт зафиксирован строкой в шапке `src/cli/index.ts:2`:
  `// Контракт: команды не вызывают process.exit — код выхода задаётся здесь через process.exitCode.`
- Проверки после правки: `npx tsc --noEmit` → exit 0; вызовов `process.exit(` в `src/cli/` — 0
  (остались только комментарии-объяснения в `cmd-apply.ts:266` и `store/reset.ts:51` и легаси-обёртки,
  которые удаляются в T-02); `resume show nosuch` → код 1; `resume register` без имени → код 1; оба пути
  завершаются штатно.
- Пункты про меню (TTY) не проверялись — меню интерактивно и в этом окружении недоступно; они оставлены
  открытыми за владельцем.
