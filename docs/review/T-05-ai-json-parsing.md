# T-05 — Единый парсинг ответов модели

- **Приоритет:** P1 — REVIEW.md § I **D3**
- **Этап:** 1
- **Зависимости:** нет
- **Объём:** 2 файла + 2 точки использования

## Проблема

В проекте **два** независимых парсера ответа ИИ и **два** способа достать список из результата:

- `src/text-utils.ts:5-10` — `parseJSON`: снимает фенсы ```, `**`; fallback по первому `{`…`}` в текущем
  коде **отсутствует** (несмотря на описание в отчёте) — его и надо добавить при объединении;
- `src/domain/grade-resume.ts:9-31` — `safeJsonParse`: своя эвристика экранирования кавычек и среза
  управляющих символов; общий `parseJSON` при этом **не** используется;
- извлечение массива: `src/domain/judge/judge.ts:153` (`parsed.verdicts || []`) и
  `src/domain/cover-letter/cover-letter.ts:170` (`parsed.letters || []`).

Практический эффект: улучшения в одном парсере не доходят до оценки резюме, а поведение при «почти JSON»
различается между шагами.

## Что сделать

- [ ] В `src/text-utils.ts` собрать **один** `parseJSON<T>(raw)`: стратегии объединить в порядке
      (1) прямое `JSON.parse`, (2) снятие фенсов/разметки, (3) fallback по границам `{`…`}`, (4) санитайз
      управляющих символов и незаэкранированных кавычек из `safeJsonParse`.
- [ ] Добавить `asList<T>(parsed, key?)`: массив → как есть; объект → `parsed[key]` если массив; иначе `[]`.
- [ ] `src/domain/grade-resume.ts`: удалить `safeJsonParse`, использовать общий `parseJSON`.
- [ ] `judge.ts:153` и `cover-letter.ts:170`: заменить обе эвристики на `asList(parsed, 'letters')`
      (для судьи — `asList(parsed, 'verdicts')`).
- [ ] Логировать причину неудачи парсинга один раз (`log.warn`) — сейчас поведение при сбое различается:
      один путь бросает исключение, другой возвращает пустой результат. Выбрать единый контракт и описать его
      в JSDoc: **`parseJSON` бросает, `asList` не бросает**.

## Риски

Слияние эвристик может изменить поведение на «грязных» ответах: старый `safeJsonParse` был мягче,
`parseJSON` — строже. Поэтому стратегии складываются **последовательно** (мягкая — последней), а не заменяют
друг друга, и добавляется лог, чтобы такие случаи были видны.
