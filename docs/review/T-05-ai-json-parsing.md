## Риски

Слияние эвристик может изменить поведение на «грязных» ответах: старый `safeJsonParse` был мягче,
`parseJSON` — строже. Поэтому стратегии складываются **последовательно** (мягкая — последней), а не заменяют
друг друга, и добавляется лог, чтобы такие случаи были видны.

## Реализовано

- **`src/text-utils.ts`**: один `parseJSON<T = any>(raw)` вместо двух реализаций. Стратегии применяются
  последовательно, первая успешная выигрывает: (1) `JSON.parse` как есть; (2) снятие markdown-обёртки
  (фенсы ```json/```, `**`); (3) срез по границам `{…}` — новая возможность, из-за неё ответ с
  преамбулой/эпилогом больше не теряется; (4) санитайз: управляющие символы заменяются на пробел,
  эвристика по незаэкранированным кавычкам перенесена из `safeJsonParse` дословно (в ней `p1` не может
  содержать `"` из-за `[^"]*`, поэтому фактический эффект даёт только замена control-символов — поведение
  сохранено 1:1, «улучшать» регулярку в этом тикете не стали).
- **Контракт (JSDoc)**: `parseJSON` **бросает** `Error`, если не сработала ни одна стратегия, и перед этим
  ровно один раз пишет `log.warn` с причиной и превью ответа (200 символов); `asList(parsed, key?)`
  **не бросает** — массив как есть, либо `parsed[key]`, если это массив, иначе `[]`.
- **`src/domain/grade-resume.ts`**: `safeJsonParse` (30 строк) удалён, используется общий `parseJSON`.
  Мягкие стратегии внутри нового парсера сохранены, поэтому результат на «почти JSON» тот же, а выигрыш —
  в общем наборе стратегий (фенсы/`**`/границы `{}`) и в едином логе причины сбоя.
- **`src/domain/judge/judge.ts`**: `parsed.verdicts || []` → `asList(parsed, 'verdicts')`.
- **`src/domain/cover-letter/cover-letter.ts`**: `parsed.letters || []` → `asList(parsed, 'letters')`.
- **Отступления от плана / побочные эффекты:**
  - пустой вход: прежний `parseJSON` возвращал `null`, теперь бросает — это и есть требуемый единый
    контракт. Наблюдаемого изменения нет: все три потребителя проверяют пустой ответ до парсинга
    (`if (!text) return null`), а `log.debug` в `grade-resume` остался прежним.
  - если модель вернёт `verdicts`/`letters` не массивом (строкой, объектом), `asList` отдаёт `[]`, тогда как
    прежний `for…of` по строке прошёл бы по символам; на `null`-корне прежний код падал бы с `TypeError`.
    Это осознанное ужесточение на невалидном ответе, нормальный путь не затронут.
  - парсер теперь тянет `logger` (единственная новая зависимость `text-utils.ts`); циклов нет —
    `logger → paths`, обратных импортов нет.
