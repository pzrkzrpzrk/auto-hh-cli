## Риски

Низкий: правка — только отображение (read-only). Единственный нюанс — объём коллекции: если записей много,
`load()` выгрузит всё; при необходимости ограничиться последними N (сортировка + `limit`) — но это уже
изменение поведения, поэтому вынести в отдельный тикет, если понадобится.

## Реализовано

`src/cli/cmd-history.ts` переписан целиком (28 → 61 строка): читает Mongo через
`history.load()`, файл `data/history.json` больше не упоминается (`fs`/`path` из импортов ушли).

- **Сортировка добавлена:** `lastByAt(items, n, key)` сортирует по `at` перед `slice(-20)` / `slice(-10)`.
  Это вынужденная правка: Mongo не гарантирует порядок документов, а `slice(-n)` осмыслен только на
  отсортированных данных — иначе «последние 20» могли оказаться произвольными.
- **Счётчики в шапке:** `=== История откликов: откликнулся N, просмотрено без отклика M, всего T ===`.
  Отдельные заголовки блоков сохранены ровно как были (`=== Откликнулся (N) ===`,
  `=== Просмотрено, без отклика (N) ===`), строки — в том же формате `<title> @ <employer> [<score>/10]`
  + отступ с URL.
- **JSON-режим** (`-j`, используется меню) сохранён: `{ applied, seenOnly }`; `applied` теперь содержит
  `meta` (`title`, `employer`, `url`, `score`, `digestOnly`) — это результат правки `load()` в T-07.
- Ошибка чтения Mongo больше не «молчит»: `log.error` + `process.exitCode = 1` (контракт T-03).

### Проверки на живой базе (`autohh`)

- `npx tsx bin/auto-hh history` →
  `=== История откликов: откликнулся 184, просмотрено без отклика 593, всего 777 ===`, далее реальные
  вакансии с компаниями и оценками (до правки печаталось `No history yet.`).
- `npx tsx bin/auto-hh history --json` → exit 0 за 6 с, 2071 строка JSON, `applied` содержит `meta`.
- `db.history.countDocuments()` = 777, `{status:'applied'}` = 184, `{'meta.digestOnly':true}` = 184 —
  цифры совпадают с выводом команды.
- grep по `src/` и `README.md`: ссылок на `data/history.json` — 0.
