# T-13 — Cron через `node-cron`, а не самописный парсер

- **Приоритет:** P2 — REVIEW.md § II **K3**
- **Этап:** 4
- **Зависимости:** нет
- **Объём:** 37 строк удалённого кода

## Проблема

`src/cli/cmd-schedule.ts:24-60` — собственный парсер cron: разбор полей, `*`, числа, шаги, проверка
«следующего запуска» перебором минут. При этом в зависимостях есть `node-cron@4.2.1`, у которого уже
есть `ScheduledTask.getNextRun(): Date | null`
(`node_modules/node-cron/dist/cjs/tasks/scheduled-task.d.ts:33`).

Самописный матчер к тому же неверно обрабатывает диапазоны и `*/n` со смещением в дне недели, то есть
подсказка «следующий запуск» может расходиться с реальным расписанием, по которому задача будет запущена.

## Что сделать

- [ ] Удалить `getNextDate`/матчер (`:24-60`), оставив валидацию выражения через `node-cron`
      (`cron.validate(expr)`).
- [ ] Планировать задачу так же, как сейчас (`cron.schedule`), и брать `task.getNextRun()` для вывода
      «следующий запуск».
- [ ] Если задача уже создана и `getNextRun()` возвращает `null` (выражение без будущих запусков) —
      вывести явное сообщение вместо `undefined`.
- [ ] Формат вывода даты оставить прежним (та же локаль/форматирование, что и сейчас).

## Definition of Done

- [ ] В `cmd-schedule.ts` нет ручного разбора cron-полей; используются только `cron.validate` и задача `node-cron`.
- [ ] `npx tsc --noEmit` → exit 0.
- [ ] Вывод совпадает с реальным запуском: для `*/5 * * * *` подсказка показывает ближайшую минуту,
      кратную 5, а для `0 9 * * 1-5` — ближайший будний день 09:00 (проверить 3-4 выражения, включая те,
      что раньше считались неверно: диапазон `1-5` и `*/2`).
- [ ] Пункт меню «Планировщик» открывается и печатает расписание без ошибок.

## Проверка

```powershell
npx tsc --noEmit
node -e "const c=require('node-cron'); const t=c.schedule('0 9 * * 1-5',()=>{}); console.log(c.validate('0 9 * * 1-5'), t.getNextRun()); t.stop();"
```

## Риски

Проверено: `node-cron@4.2.1` поставляет **собственные** типы (`node_modules/node-cron/package.json:14` →
`dist/cjs/node-cron.d.ts`), поэтому `getNextRun(): Date | null` виден компилятору и обходной приём
`as unknown as { getNextRun(): Date | null }` **не нужен**. При этом в `devDependencies` лежит устаревший
`@types/node-cron@^3.0.11` (`package.json:45`), в чьём `ScheduledTask` метода `getNextRun` нет вовсе
(`node_modules/@types/node-cron/index.d.ts:26`): пакет типов не используется (TS предпочитает типы из
самого `node-cron`) и только путает. Удалить его вместе с этой правкой — если оставить, при смене разрешения
типов можно получить ошибку компиляции.
