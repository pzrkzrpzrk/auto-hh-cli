# T-10 — `grade-resume`: единая таблица категорий и вынос промпта

- **Приоритет:** P2 — REVIEW.md § I **D13**
- **Этап:** 3
- **Зависимости:** нет
- **Объём:** 2 файла

## Проблема

1. **Категории оценки объявлены дважды** — `src/cli/cmd-grade-resume.ts:49-55` (вывод в Markdown)
   и `:127-131` (вывод в консоль): одни и те же ключи и веса 25/25/20/20/10, но обходятся двумя разными
   циклами и продублированными подписями. Изменение веса или добавление категории требует правки в двух местах.
2. **Промпт (95 строк) лежит inline** — `src/domain/grade-resume.ts:33-95`, тогда как у `judge` и
   `cover-letter` промпты вынесены в `system-text.ts`. Из-за этого промпт оценки незаметен рядом с логикой
   и не попадает в общий обзор текстов.

## Что сделать

- [ ] В `src/domain/grade-resume.ts` объявить
      `export const CATEGORIES = [{ key, title, max }]` (25/25/20/20/10) и использовать её как
      **единственный** источник списка категорий и весов.
- [ ] `cmd-grade-resume.ts:49-55` и `:127-131`: оба вывода обходят `CATEGORIES` (один цикл + параметр формата),
      подписи берутся из `title`.
- [ ] `src/domain/grade-resume.ts:33-95`: промпт перенести в новый `src/domain/grade-resume/system-text.ts`
      по образцу `src/domain/judge/system-text.ts`.
- [ ] При желании — вывести `max` в промпт-текст из `CATEGORIES` нельзя (промпт статичный, с рукописными
      описаниями), поэтому оставить в промпте как есть и добавить комментарий-якорь: при изменении весов
      правку промпта не забыть (или дополнительно проверить согласованность в рантайме).

## Definition of Done

- [ ] Числа 25/25/20/20/10 встречаются в `src/` только внутри `CATEGORIES`.
- [ ] `src/domain/grade-resume.ts` содержит логику вызова модели, но не содержит текста промпта.
- [ ] `npx tsc --noEmit` → exit 0.
- [ ] Вывод оценки резюме не изменился ни в консоли, ни в `.md`-файле (сравнить с сохранённым примером).

## Риски

Низкий: тикет не меняет ни данные, ни API модели. Единственная тонкость — формат `.md`-вывода
(таблица) должен остаться побайтово прежним, поэтому при рефакторинге вывода держать тот же порядок
категорий и ту же разметку.
